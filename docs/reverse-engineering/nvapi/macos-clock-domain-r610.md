# macOS RM: 时钟域枚举与逐域实时频率（610.57.04）

两个 8 字节只读 CLK 控制，实测在 TU116 / GTX 1650 SUPER / macOS 15.8.1 / NullMoth 2.0.4 上
`NV_OK` 并返回真实数据。父命令空间 `0x2080` 属于子设备句柄。

## `0x20809001` — 枚举可报告域

请求 `{u32 mode, u32 0}`，回答 `{u32 mask, u32 mode}`：

| mode | 返回 mask | 备注 |
| --- | --- | --- |
| 0 | `0x03FC007F` | 实测原值，位 0–6 与 18–25 |
| 1 | `0x0380007F` | 实测原值，位 18–25 + 0–6 中的一部分 |

`mask` 之外的状态、以及 mode 语义（"全量" vs "子集"）都未定，产品里按位原样报告。
`0x20809002` 是同区的 16 字节 id，本卡回 `0x56`（GSP 表里根本没有行），不要再用。

## `0x20809006` — 单域实时频率

请求 `{u32 version, u32 domain_bit}`，回答 `{u32 version, u32 kHz}`。

* `version` 必须为 1：api 侧 `sub_31D50` 先判 `*a2 == 1`，填 0 或 3 以上实测都回 `0x1f`。
* `domain_bit` 取 `0x20809001` 报出的位；实测 bit1 连读得 1545076 / 1545069 kHz（~1545 MHz，标称 1545），随负载小幅抖动，符合"实时频率"而不是常量。
* 载荷只有 8 字节，送 12 字节同样 `0x1f`。

## 未通：`0x20809014`（锁定通道）

`libnvidia-api.so.1` 的 `sub_10A730`（调试串 `dmal/common/common_clock.c:162`、
`cDeviceMapTargetToActualFrequency`）就是它的发放者：

```
v23[1] = 1; v23[3] = a3; v23[5] = a4;      /* 648 字节块 */
v10(v8, a2, 8320, &v22);                    /* 8320 = class 0x2080，取对象句柄 */
sub_9E560(v12, s[140], v22, 545296404, v23, 648, 0);
```

即参数块本身没有版本校验（`a2[1]` 恒 1），行是 648 字节，对象必须是 `0x2080` 类的句柄。
但在这张卡上，s（子设备）、d（设备）、c（client）三种句柄 × `+0` 取 1/2/4/5/6/7/`0x10038`/`0x2009C`
× `+4` 取 1 或 4095 × `+8/12/16/20` 各种取值组合，全部回 `0x1f`（`d`/`c` 上位句柄先回 `0x56`）。
下一步要么拿到 `v10` 那一层 getter 的返回类型（句柄是否另有其物），要么找到 `sub_9E560` 的其他调用者
读出同族可写块的版式。

## 探测配方

```
/tmp/mini/mini13 20809001 8  "set:0=0"      # 枚举
/tmp/mini/mini13 20809006 8  "set:0=1;4=1"  # 读 bit1
```
